# 示例数据文件说明

这些文件是**故意做脏**的，用来演示"上传 → 清洗 → 出图"这条链路。
上传一个完美文件说明不了任何问题；上传一个**跟真实系统导出的一模一样脏**的文件，
才能看出系统到底有没有真本事。

> 重新生成：`cd samples && ../backend/.venv/bin/python generate_samples.py`

---

## 文件清单

| 文件 | 编码 | 用途 |
| --- | --- | --- |
| `电商销售_干净数据.csv` | UTF-8 | **对照组**。480 行标准数据，直接上传应当零问题 |
| `电商销售_脏数据_GBK乱码.csv` | **GBK** | 演示中文乱码 + 文本型数字 |
| `电商销售_脏数据_Excel花式.xlsx` | — | 演示 Excel 的典型陷阱（最像真实报表） |
| `电商销售_脏数据_编号丢零.csv` | UTF-8 | 演示学号/编号前导零丢失 |

## 每个文件埋了什么坑，系统应该怎么处理

### 1. `电商销售_脏数据_GBK乱码.csv`（在 Windows 上双击打开会直接乱码）

| # | 埋的坑 | 正确的处理 |
| --- | --- | --- |
| 1 | 文件是 **GBK** 编码，不是 UTF-8。按 UTF-8 读会变成 `�������,ʡ��` | 自动识别编码（尝试 UTF-8 → 失败则试 GB18030/GBK），读出来必须是「订单编号,省份,…」 |
| 2 | 部分「销售额」写成带千分位的**文本**，如 `"1,464.32"` | 识别为数字 1464.32，能参与求和（若当字符串处理，求和结果会是 0） |
| 3 | 部分「订单量」是**全角**数字 `５４６３９` | 转换成半角数字 54639 |
| 4 | 每 20 行插了一个**空行** | 丢弃空行，不计入行数 |
| 5 | 每 7 行有一个**缺失值** | 标出缺失位置，让用户选择"删除该行"或"用平均值/中位数填充" |
| 6 | 最后一行是**"合计"行**（报表常见） | 识别并丢弃，否则总额会翻倍 |

**验收标准**：清洗后行数应为 **480 行**，且「合计」行不出现。

### 2. `电商销售_脏数据_Excel花式.xlsx`（最像真实报表，坑最深）

| # | 埋的坑 | 正确的处理 |
| --- | --- | --- |
| 1 | 第 1 行是**合并单元格的大标题**「华东华南区电商销售明细表（2024 年度）」 | 识别出它不是表头 |
| 2 | 第 2 行**空行**，真表头在**第 3 行** | 自动定位到真正的表头行 |
| 3 | 「省份」列有 **26 处纵向合并**，只有每组第一行有值，其余是空的 | **向下填充**（合并单元格还原），否则会凭空多出大量"缺失省份" |
| 4 | 「月份」写成了文本 `2024年1月` 而不是数字 | 提取出数字 1，或至少保证 12 个月份能被正确分组 |
| 5 | 每 9 行有一个**缺失值** | 同 GBK 文件的处理方式 |
| 6 | 每 25 行一个**空行** | 丢弃 |
| 7 | 多出一列「备注」，绝大部分为空 | 保留但标出"高缺失率"，不参与统计 |
| 8 | 表尾有「制表人：张三…」 | 丢弃 |
| 9 | 文件里还有**第二个工作表**「说明」 | 让用户选择要分析哪个工作表，默认第一个 |

**⚠️ 第 3 条是重点**：如果系统不做"向下填充"，省份列会变成大量空值，
后面"按省份汇总"的结果会**完全错误**（钱全跑到"未知省份"里去了）。
这是最容易被忽略、也最能体现工作量的一个坑。

### 3. `电商销售_脏数据_编号丢零.csv`

| # | 埋的坑 | 正确的处理 |
| --- | --- | --- |
| 1 | 「学生编号」以数字形式存储，**开头的 0 已经丢了**（`202300001` → `202300001` 看似正常，但若原始是 `00123` 就变成 `123`） | 编号类字段应当作文本处理；系统要提醒"该列看起来像编号，建议按文本导入" |
| 2 | 省份里**夹杂空格**（`"广 东"`） | 去掉首尾与内部多余空格 |
| 3 | 每 15 行**又插了一遍表头**（分页导出的产物） | 识别并丢弃重复表头行 |

## 演示建议（给老师看的时候怎么讲）

1. **先传干净文件** —— 秒过，证明正常路径没问题。
2. **再传 GBK 乱码文件** —— 对比"如果直接按 UTF-8 读会是什么样"，说明为什么要做编码识别。
3. **最后传 Excel 花式文件** —— 展示"省份纵向合并"还原前后的差别：
   - 不还原：按省份汇总会出现一个巨大的「（空）」；
   - 还原后：8 个省份的金额与干净文件**完全对得上**。

第 3 步是整个数据模块最有说服力的 30 秒。
